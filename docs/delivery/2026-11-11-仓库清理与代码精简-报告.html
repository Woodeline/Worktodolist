04 · 配置

三处会真出问题的设定

CI 的 Node 版本与代码要求不符

qa-css-check.mjs / qa-hooks.mjs 用了 node:fs 的 globSync（Node 22 才有），但两个 workflow 都钉着 node-version: 20 —— CI 上 test:ui 会在 import 阶段直接 SyntaxError。 已升到 22，并在 package.json 补上 engines.node >= 22（此前并不存在，只是约定）。

Windows 专用包卡住了别的平台

@esbuild/win32-x64 原在 devDependencies，在 macOS / Linux 上 npm ci 直接 EBADPLATFORM 失败。挪进 optionalDependencies 后 平台不匹配只是跳过。已用 npm ci --dry-run 在 darwin/arm64 实测通过 （输出 removed 1 package，正是跳过它）。

dayjs 是 dev 依赖，却声明成运行时依赖

dayjs 全仓只被 styleguide.jsx 使用，而样式指南不进产品构建 （vite build 只以 index.html 为入口，dist/ 里没有 styleguide）。 已移入 devDependencies，package-lock.json 同步更新。

提醒链路：Python 已被 Rust 取代

register_reminder_task.py 原本注册的是 python daily_reminder.py， 而 reminder.rs 早已支持 Worktodolist.exe --reminder 隐藏实例。 注册脚本改写为拉起该入口：不再需要机器上装 Python，提醒文案与解析只有一个实现。 顺带加上 --time / --delete / --dry-run。

README.md 的「每日提醒」段落与目录结构说明已同步改写； start-mac.sh 里「npm install --force」的提示也改回普通安装。

06 · 未动

看到了但没改的（建议留着下一轮再议）

  • useTodoStore 每次渲染返回新对象，40 多个字段全在同一个字面量里， 任一状态变化都会让所有消费者重渲染。真要治，得给整张返回值加 useMemo 并保证每个函数引用稳定 —— 这正好踩在「Hook 数量必须恒定」那条铁律旁边，收益在几百条任务规模下几乎为零，风险却不小。

  • proposalToIntent 的 create / edit 分支已无生产者 （对应的工厂这轮删了）。保留是因为它是 dispatch 的契约面，将来若对话页改走提议模型可直接复用； 已在文件头注释里写明现状。
  • scripts/add_bin_to_user_path.py、install_topydo_shim.py 全仓零引用（环境一次性脚本，共 3.7 KB）。没删是因为 topydo 协作属于项目长期价值，可能还要用。
  • index.css 6871 行、约 20 个选择器出现两次。逐条看过，多为明暗分档或 媒体查询里的必要覆盖，合并会破坏令牌门禁的现有断言，不动。
  • CHANGELOG.md 没加本次条目：它按发版节奏写，这次是纯维护、 无用户可见行为变化，等下次发版一并记。
