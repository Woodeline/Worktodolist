## 三、问题清单

### P0-1 · CI 引用了已删除的脚本，任何推送都会构建失败

**证据**

```
.github/workflows/build-windows.yml:62:  run: npm run test:guard && npm run test:nl && npm run test:ui
.github/workflows/build-macos.yml:75:    run: npm run test:guard && npm run test:nl && npm run test:ui
```

实测：

```
$ npm run test:nl
npm error Missing script: "test:nl"
npm error Did you mean this?
npm error   npm run test:ui # run the "test:ui" package script
```

**原因**：`src/lib/nlRules.js` 与它的 44 条金标准语料在本轮在途改动中被删除（自然语言解析层退场），`package.json` 里 `test:nl` 脚本也一起摘掉了 —— 但**两条 workflow 的注释和命令行都没跟着改**。

**影响**：标签推送不再产出 Release 资产，`main` 分支的构建也是红的。因为 CI 在 Rust 编译**之前**跑门禁，失败会直接中断，连 artifact 都没有。

**建议**：两处都改成 `npm run test:guard && npm run test:ui`，并把注释里的「NL 词表」一并删掉。

### P1-4 · 没有 lint，`react-hooks/exhaustive-deps` 无人把关

全仓无 `.eslintrc*` / `eslint.config.*` / `.prettierrc` / `.editorconfig`。

自定义的 `qa-hooks.mjs` 只查一件事（43 文件无「提前 return 之后调 Hook」），查不到依赖数组写错 —— 而这是 React 最高频的 bug 类。

**现存实例**：`App.jsx:658` 的依赖是 `[isCalendar, store]`，而 `useTodoStore`（`useTodoStore.js:733`）**每次渲染都返回新的对象字面量**。所以这个 effect 每次渲染都跑一遍（靠 `prevCalendarRef` 兜住幂等，行为正确、纯属浪费）。这是 `exhaustive-deps` 会指出、而当前门禁看不见的典型。

**建议**：加最小 ESLint 配置（`eslint-plugin-react-hooks` 的 `rules-of-hooks` + `exhaustive-deps` 两条就够），先 `--max-warnings` 放宽跑起来，别一次性开全量规则。或者至少把 `useTodoStore` 的返回值 `useMemo` 化，并给 `qa-hooks.mjs` 补一条「依赖里出现整个 store」的检查。

### P1-5 · 15 个孤儿样式，其中 5 组是已被替换的旧实现

扫 `index.css` 全部 499 个类名，与源码里出现过的标识对账，**源码零引用**的有：

```
.cal-range-seg (.is-start .is-mid .is-end .is-single)   ← 旧版区间段，已换成 .cal-bar-strip
.settings-check / .settings-check-text / .settings-badge / .settings-warn   ← 设置页已改只读
.topbar-done-count      ← 底部状态栏删除后的残留
.proposal-actions / .tool-errors / .tool-input-temp / .ctx-kbd / .drawer-preview-text / .w3
```

另有 `ToolsWall.jsx:36` 往 DOM 注入 `--tone`，而 `index.css` 里 `var(--tone)` 出现 **0 次** —— `wallConfig.js` 的 `GROUP_TONES` 是一整套悬空死代码。

**影响**：不影响运行，但会让"读 CSS 猜行为"的人（包括 AI Agent）反复踩空；`.cal-range-seg` 这类残留还会诱导人去恢复一个已不存在的功能。

**建议**：删掉上述选择器与 `GROUP_TONES` 注入；`qa-css-check.mjs` 顺手加一条反向检查（CSS 里定义、源码里零引用的类只允许在白名单内），防止再长回来。

## 五、值得说清楚的优点

不是客套，这几项是真的做得比一般个人项目硬：

1. **三条红线字面兑现**：Rust 侧 `atomic_write` 的 tmp+rename 有单测（`workspace.rs`），冲突只在 focus 时"检测"不"上锁"，`configStore` 一能力一键、可 `clear`。没有一处偷偷换成 SQLite 或联网。
2. **对抗用例真的在测坑**：`test:attack` 的 C1–C8 专门打「完成窗口内撤销」「删除后撤销」「幽灵任务」这些组合时序 —— 这类 bug 单测最爱漏。
3. **权限收得紧**：`capabilities/default.json` 只开 11 项，`core:default` + 7 个 window 命令 + `dialog:allow-open` + `notification:default`，没有任何 `fs:*` 通配。
4. **CSP 不是摆设**：`object-src 'none'`、`base-uri 'self'`、`script-src 'self'`，dev 与 prod 分开写。
5. **命令执行不拼 shell**：`git.rs` 全程 `Command::new("git").args([...])`，`git add --` 还带了 `--` 防误解析。
6. **备份清理有边界单测**：`backup_family` 明确拒绝 `todo-abcdefgh-1.txt` 这类名字，避免 prune 误删用户文件。
7. **文档索引零失效**：20 条链接逐条核对可打开，分区（guide/design/delivery/plan）与实际文件完全一致。
8. **版本号 5 处一致**：`package.json` / `package-lock.json` / `tauri.conf.json` / `Cargo.toml` / `Cargo.lock` 全是 1.4.0。
