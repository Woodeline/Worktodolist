Redesign Plan · Tools Page

工具页卡片式改造方案

基线 v1.0.3 修订 + UI 外壳 v2（工作区未提交） 现有工具 4 个 · 分组 2 类 单测 358 QA 响应档 28 2026-10-17
结论

工具页从「抽屉式主从界面」改为两态结构：卡片墙（目录态）+ 工具工作区（工作态）。墙负责发现与进入——工程计算、待办数据两个分组各成一张卡片网格，每组末尾留一张虚线预留卡，扩展位在界面上可见；点卡片才进入工作区，工作区本身零改动。「加工具只改 registry」的承诺不变，且因期望值从 registry 现算，新工具自动进入 QA 门禁。最大工作量不在卡片，而在 qa-tools / qa-responsive 两组断言的迁移（§10）。

01

现状与四个具体问题

改版前的对账

当前工具页是 ToolsPage.jsx 的「左清单 + 右工作区」：左栏 176px（--sidebar-w）竖排 4 个工具，右侧 .tool-pane 挂当前工具。这套结构在 RTI 单工具时成立，四个工具之后就露出下面四个问题：

  1. 发现成本全押在打开之后。左栏每项只有两行文字（名称 + 截断描述），tags、风险徽标（只读 / 会写入 todo.txt）、beta 状态一律看不到——用户必须先打开才能判断是不是想要的工具。
  2. 176px 侧栏先到头。工具名 + 描述在这个宽度里频繁换行；工具从 4 个涨到 8 个时，侧栏要滚动，而右侧工作区还空着一半。
  3. 没有「家」。进来直接落在清单第一个工具（RTI）的工作区；想看全貌要先在左栏里挨个试。
  4. 扩展位不可见。registry 加一条只是在左栏多一行，界面本身不表达「这里还会长出新模块」，与路线图里「抽屉做成柜子」的目标相反。

另外，窄屏（≤768）现行降级是把左栏摊成横向段控条：描述、收藏/最近标记全部隐藏，工具只剩名字——发现能力直接归零。卡片网格天然响应式，这一档反而是强项。

02

整体布局结构：两态

目录态 / 工作态，外壳其余部分不动

工具页内部新增一个模式状态 mode: 'wall' | 'tool'。外壳（46px 活动栏 + 36px 上下文条 + 状态栏）、工作态本体（ToolShell / ToolBoundary / 懒加载 / 提议通道）全部沿用，只改 .tools 容器里的内容分支。

.tools
├─ mode = 'wall'（目录态）
│   ├─ .tools-wall-head      标题「工具集」+ 模块计数 + 搜索框
│   ├─ .tools-sec × N        分组区（工程计算 / 待办数据 / …，一层封顶）
│   │   ├─ .tools-sec-head   组色条 + 组名 + 计数 + 组注（GROUP_NOTES）
│   │   └─ .tools-cards      repeat(auto-fill, minmax(228px, 1fr)) 卡片网格
│   │       ├─ .tools-card × M            工具卡（见 §03 解剖）
│   │       └─ .tools-slot × 1            虚线预留卡（组内 < 4 个工具时才渲染）
│   └─ .tools-none           搜索无命中时的空态
└─ mode = 'tool'（工作态）
    ├─ .tool-head            页头：← 返回按钮 + 面包屑 + 标题 + 风险徽标
    └─ ToolBoundary + Suspense + 当前工具组件   —— 与现在完全一致，零改动

状态机

进入工具页 ──► wall ──点击卡片/Enter──► tool ──←按钮或Esc──► wall
                  ▲                                                        │
                  └──────────── 对话页 tool.open（request.id）──────────────┘
                      直达 tool，不经过 wall；返回后不重复触发（seq 去重）

与现有机制的接法

  • MRU / 收藏：沿用 lib/toolStorage.js 的 loadToolMeta / touchMru / toggleFavorite，只改消费方（左栏 → 卡片排序与「收藏」置顶组）。
  • 事件线：卡片打开复用 logToolEvent('tool.open', { toolId, source: 'card' })，与左栏的 source:'nav' 区分来源。
  • 提议确认通道：不变——仍只有 capabilities.writes 的工具拿得到 propose。
  • 懒加载缓存：不变——LAZY Map 按 id 缓存，两态切换不重挂组件。

①组色竖条（3px）左侧通栏竖条承担分组编码：工程计算 = --accent 青，待办数据 = --ok 绿。颜色只编码「归属」，不编码优先级。

⑥底行：风险徽标 + MRU发丝线隔开。风险徽标复用现有 .tool-risk 三态（quiet 只读 / warn 会写入 / danger 会联网）；MRU 前三名显示「最近用过」。

04

模块分类方式

一层分组封顶，与路线图约束一致

分组直接沿用 registry 的 GROUPS（工程计算 / 待办数据），registry 契约零改动。墙内的呈现规则：

规则说明
分组即分区每个分组一个 .tools-sec 区：组色条 + 组名 + 计数徽标 + 右侧灰色组注。组注放在外壳侧常量表 GROUP_NOTES（如工程计算「试验数据 → 寿命参数」、待办数据「读 todo.txt 只读投影」），不进 registry——registry 仍只描述「是什么」。
收藏置顶有收藏时，墙顶先出「收藏」区（无组色条，星标图标），收藏项从原分组消失。无收藏则不渲染该区。
组内排序收藏 > MRU 近三日 > registry 声明序。让常用的浮上来，但不手写排序逻辑。
搜索即平铺有查询词时取消分组，所有命中卡片平铺按 MRU 排序（与现行 flat 行为一致）；无命中出空态。
兜底组group 未登记的工具进「其它」区（现行逻辑保留），保证漏登记也可见、不消失。
不做二级分组之下不再分子类。工具超过一屏时靠滚动 + 搜索，不做三级导航、不给区头加折叠。

06

响应式适配策略

auto-fill 网格 + 一档内容降级

卡片墙用 repeat(auto-fill, minmax(228px, 1fr)) 自动分栏，没有断点硬编码列数；只在窄档做一次内容降级。所有档位沿用既有红线：minmax(0, 1fr) 防隐式列撑爆、无横向溢出。

档位卡片列数适配动作
≥ 12804完整体；搜索框 220px 右置于页头
900 – 12793同上
640 – 8992完整体（tags 仍全显）
< 6401desc 收 1 行、tags 最多 2 个、搜索框换行全宽、组注隐藏
coarse pointer同宽档星标命中区扩到 ≥44px（padding 补偿）；整卡可点天然满足 44px

对比现行窄屏方案（段控条隐藏 desc / 旗帜 / 组头），卡片墙在 390px 下反而信息更全：单列大卡保留描述、标签、风险徽标——发现能力不降反升。

07

未来扩展机制

三条通道，全部已有雏形

① 加 工 具

tools/ 放组件 + registry 加一条（group 填已有 id）→ 自动出现在对应分组网格，自动进入 qa-tools 门禁，对话页 keywords 自动可达。壳零改动。

② 加 分 组

GROUPS 加一行 + 外壳侧 GROUP_TONES / GROUP_NOTES 各加一行 → 新区自动成区。组色从青 / 绿起按需扩，仍不新增色相以外的编码。

③ 预 留 卡

组内工具数 < RESERVED_SLOT_LIMIT（=4）时，网格末尾渲染一张虚线预留卡；满 4 张自动隐藏。它同时承担两个职能：填平最后一行 + 预告「这里还会长」。

新增常量（全部放在墙组件文件头，registry 不动）

const RESERVED_SLOT_LIMIT = 4;      // 组内满 4 个工具后隐藏预留卡
const GROUP_TONES = { engineering: 'var(--accent)', todo: 'var(--ok)' };
const GROUP_NOTES = { engineering: '试验数据 → 寿命参数', todo: '读 todo.txt 只读投影' };

QA 自动扩展的原理：qa-tools 的期望值本来就全部从 registry 现算（现行设计），卡片断言照此办理——卡片数 = visibleTools().length + 预留卡数（按 GROUPS 现算），所以每加一个工具，门禁自动多查一张卡，脚本不用改。

过程中修掉的三个真问题

  1. 墙重挂载使契约循环的卡片节点全部失效。旧左栏不卸载所以从未暴露；两态下每进出一趟工具，墙整体重挂载，循环外捕获的 DOM 节点从第二轮起全是 detached。修法：每轮按名称重新取卡。
  2. 预留卡不是 .tools-card。卡片数断言一开始把虚线预留位算进了工具卡数（4 vs 6）。修法：工具卡与预留卡分开计数，分别对 visibleTools().length 与按组现算的预留数。
  3. 注释里的类名写法会污染 css-check。「.tools-nav* 系列随之删除」被类名提取器当成真实类名登记。修法：注释里不写点号类名。
