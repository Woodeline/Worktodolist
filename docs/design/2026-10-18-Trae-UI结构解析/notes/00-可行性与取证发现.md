## 1. CDP 路线成立（Step 0 门禁通过）

| 项 | 实测 |
|---|---|
| 宿主 | Trae 1.107.1 fork，`Electron/39.2.7`，`Chrome/142.0.7444.235`，V8 14.2 |
| `--remote-debugging-port` | **被接受**（Chromium 136+ 的「默认 user-data-dir 忽略调试端口」限制未触发，因为探针用了独立 profile） |

**踩到并已修的坑**：`/json/version` 约 0.5s 就响应，但此刻 `/json/list` 仍是 `[]`——page target 尚未注册。若按「端点可达」判成功，后续所有 DOM 采样都会拿到空树。判据必须改成**轮询到 `"type":"page"` 出现**（已固化进 `tools/trae-cdp.ps1` 的 launch）。

**另一个坑（同项目老病复发）**：PowerShell 5.1 按 ANSI 读 UTF-8 无 BOM 的 `.ps1`，**中文注释会破坏解析**，报 `表达式或语句中包含意外的标记`。工具脚本一律 ASCII；`.mjs` 不受影响。

## 2. Trae 的界面不是单页，是 3 个独立渲染目标

采到的 target 清单（`GET /json/list`）：

| title | 页面 | 对应静态产物 | 含义 |
|---|---|---|---|
| `TRAE` | `out/vs/code/electron-browser/workbench/workbench.html` | `workbench.desktop.main.css` | 主工作台 |
| `Agent` | `out/vs/code/electron-browser/solo/solo-lite.html` | `workbench.desktop.main.solo-lite.css` | **SOLO/Agent 是独立窗口**，不是主窗口里的一个 div |

| `worker` | — | — | service worker |

→ 报告必须**按 target 分章**；任何「在主窗口 DOM 里找 AI 面板」的尝试都是错的。

## 3. 两套血统，取证手段要分治

- **首次引导页（`setup.html`）**：React + styled-components，类名全是 `sc-fhfEft dXhqLu` 这种哈希，`#app` 单根。**类名挖掘在此完全失效**，只能靠截图 + 文案定位 + 计算样式。
- **工作台**：VS Code 血统，`:root` 上挂 **3914 条** CSS 自定义属性（`--vscode-*`），语义化容器名可用。Agent 面板 4388 条。
- 引导页共 5 步：欢迎 → 主题（暗色/亮色/深蓝）→ 快捷键（VS Code / IntelliJ IDEA）→ …；**全程无需登录即可进入工作台**（登录只影响 AI 功能，不影响外壳 UI）。这是本次能拿到真 UI 的关键前提。
- **主题不跨 target 同步**：引导页选了暗色，工作台是暗色，但 `solo-lite` 窗口仍是亮色。→ 主题矩阵必须按 target 分别设置与验证。

## 4. 探针污染项（写报告时必须剔除，不能当产品默认行为）

- 探针带 `--disable-extensions` → 工作台右下角出现「已暂时禁用所有已安装的扩展」通知。**这是探针造成的，不是 Trae 默认状态。**
- 探针 profile 未登录 → 顶栏「登录」入口、Agent 面板登录引导均为未登录态外观。
- 探针窗口尺寸 1000×680（引导页）/ 1440×900（工作台），非用户真实窗口布局。

## 5. 事故记录：真实 Trae 实例于 11:59:35 退出

**结论：不是我杀的。** 证据链：

1. 探针启动（11:53）后，真实实例继续正常写自己的日志到 **11:58:19**（拉第三方 token、pay status、GTM 评估），两者共存约 5 分钟 → 无单实例接管。
2. 退出路径是**优雅关窗**：`Lifecycle#onBeforeCloseWindow.fire() - window ID 1` → `window.on('closed')` → `app.on(window-all-closed)` → `onWillShutdown` → `app.quit()`。被 `Stop-Process -Force` 强杀的进程**不可能**写出这条链。
3. 我那次 `stop` 的输出里**没有任何 `KILL=` 行**（只有 `STOP_LEFT=0`）→ 该命令当时一个进程都没杀。
4. 时间上与我 11:59:3x 的 stop+launch 命令巧合重叠，但上述 2、3 排除了因果。

最可能的解释：桌面上凭空多了个陌生的 Trae 窗口（探针实例），人工把探针窗口和自己的工作区窗口一起关掉了。**教训：探针会抢焦点、会在桌面产生陌生窗口，这本身就是对用户工作流的打扰——下次启动前应先打招呼，而不是默认「独立 profile 所以无害」。**

当前状态：探针实例已 `stop`，`Trae.exe` 进程数 0，9333 端口无监听。你的 Trae 需要手动重开；文件都在磁盘上，未受影响。

## 6. 工具骨架（已跑通）

- `tools/trae-cdp.ps1 launch|stop|status [-Port 9333]` —— 生命周期；launch 等 page target；stop 只按 `trae-cdp-probe` 命令行标记杀进程，绝不按进程名全杀。
- `tools/cdp-capture.mjs` —— 单命令产出 `evidence/<name>.{png,dom.json,tokens.json[,eval.json]}`。
  - `--match <url子串>` 选 target；`--click-text "文案|文案2"` 按可见文案定位并注入真实鼠标点击（哈希类名场景下唯一可靠寻址）；`--press <组合键>` 注入按键；`--max-nodes/--max-depth` 控预算。
  - 关键实现约束：页面侧函数**只能靠 `fn.toString()` 序列化**过去执行；写成 `${fn()}` 会在 Node 侧立即求值（`document` 未定义，模块直接崩）。Node 作用域变量必须当参数传。
- 复现序列：`launch` → `--match workbench.html --name E10-...` → `--match solo-lite.html --name E11-...` → `stop`。
