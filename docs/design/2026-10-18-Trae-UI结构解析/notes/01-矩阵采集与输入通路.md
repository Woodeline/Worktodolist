## 2. 本轮抓到的 4 个工具缺陷（都已修，值得进工程约定）

1. **`windowsVirtualKeyCode` 要的是 Windows VK 码，不是字符 ASCII 码。** 字母恰好相等（`P`=80=VK_P），所以命令面板能开、掩盖了问题；标点全错——`` ` `` 应是 192（VK_OEM_3）不是 96，`,` 应是 188（VK_OEM_COMMA）不是 44。同时 `code` 必须是 UI Events 规范名（`Backquote`/`Comma`），我拼成了 `` Key` ``。→ 已建 `PUNCT_VK`/`NAMED_VK` 表。
2. **命令行里写 `Control+comma` 被当成键名 `comma`**，兜底成 `vk=67`＝**Ctrl+C**。键名必须用真实字符 `,`。→ `keySpec()` 对未知键名回退时会打日志暴露，不再静默。
3. **`--click-text` 找不到目标时抛异常直接崩掉整次采集**（E36 因此丢失）。→ 改成 `CLICK=MISS` 记录后继续。
4. **页面侧函数只能靠 `fn.toString()` 序列化**；写成 `${fn()}` 会在 Node 侧立即求值（`document` 未定义 → 模块崩）。`--eval-file` 还需在工具内 `(${expr})()` 调用，否则返回的是函数本身、序列化成 `{}`。

## 3. 最重要的方法论教训：**画面字节数相同 = 该格证据无效**

E20–E25 六张图**全部 80KB、DOM 全部 103 节点**——当时我误判为「按键注入失效」。真因是一个**模态的「工作区信任」对话框**从 fixture 加载起就一直挡在界面正中（状态栏显示「受限模式」），所有按键和点击都被它吞了。

由此确立矩阵采集的硬规则：
- **每格采集后比对 PNG 字节数与 DOM 节点数**；连续多格完全相同即判定为「未进入目标状态」，必须排查而不是记录。
- **进入任何视图前先查模态层**：对话框、通知、信任提示、更新弹窗都会静默吃掉输入。`--press` 前置 `Escape|` 序列是必要卫生，不是可选优化。
- 事件是否送达要看 **DOM 侧监听器计数**（`probe-input.mjs`），不能靠截图猜；注意 `window` 捕获阶段能收到、`document` 捕获阶段可能收不到，监听点选错会得出「0 事件」的假结论。

## 4. 顺带采到的 Trae 专有事实（写报告要用）

- 活动栏 7 项：**资源管理器 / 搜索 / 源代码管理 / 预览 / 运行和调试 / 远程资源管理器 / 扩展**（「预览」「远程资源管理器」是 Trae 相对 VS Code 的差异项）。
- Trae 自己的键位提示直接印在空编辑器区：**`与 AI 对话 Ctrl+U`、`Editor 内 AI 编码 Ctrl+I`**。
- 命令面板条目是**双语**的：中文标题 + 英文副标题（如「帮助: 报告问题 / Help: Report Issue」），键位以 chip 形式右对齐。
- 源代码管理视图含 **图形（git graph）** 区块，分支标记 `main` 直接画在提交行上。
- 主题不跨窗口同步：工作台暗色，SOLO 窗口仍亮色（见 `notes/00` 第 3 节）。
