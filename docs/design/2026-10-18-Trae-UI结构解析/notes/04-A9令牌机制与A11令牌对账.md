## 1. A9：镜像是「打包期命名」，不是运行时拼接

上一轮在 §9.2 提出的机制解释（同一族令牌编译两遍、按窗口各出一份）当时只挂了「推测」级。
A9 的目标就是把它要么坐实、要么打掉。做法：在安装目录明文 bundle 里做四件事。

`tools/a9-mirror-hunt.mjs`，三种模式：

| 模式 | 问的问题 | 结果 |
|---|---|---|
| 主扫描 | 前缀出现在哪、是定义还是消费 | workbench.css 命中 **463** 次、`var()` **344** 个 / 去重 **58** 个，**定义式 0**；solo-lite.css **305/217/52**；slim.css **229/176/46**。三个 JS 各只有 **5** 条定义式（就是那 5 个渐变/滚动阴影） |
| `--verify` | 静态能否完全解释运行时 | 注册式 id **102** + 字面量 **5** = **107**；E30 快照镜像 **107**；**双向差集 0 / 0，覆盖率 100.0%** |
| `--scan-dirs` | 有没有运行时字符串拼接 | 14 种写法（`"--vscode-icube--" +` / `` `--vscode-icube--${` `` 等）在 `out/` 全量 JS/JSON/CSS 里 **0 命中** |

注册家族分布（102 条）：`status 30 · bg 17 · text 12 · icon 12 · accent 9 · cue 9 · code 5 · border 5 · special 3`
——与 §9.4 的自研族**同名同族**，所以镜像不是新起一族，是同一族的第二个命名空间。

那 5 条字面量也顺带解释了：`gradient-text-shimmer / gradient-brand / gradient-golden /
solo-title-bar-left-scroll-shadow / -right-scroll-shadow`——**颜色注册表只收颜色**，
渐变和阴影进不了注册表，只能走 CSS 字面量。这是机制层面的自洽证据，不是巧合。

另一条副产品：workbench JS 里还有 **47 次 `var(--vscode-icube--*)` / 20 个不同令牌**，
来自 JS 拼字符串注入的 Monaco 列表规则。**同一族令牌必须同时服务「静态 CSS」和「JS 生成 CSS」两种消费者**，
这就是它非挂 `:root` 不可的原因。

> 结论定级：§9.2 从 推测 → **静态实证**。同时 §12.1 新增一条坑：
> **别把静态 CSS 里的十六进制当生效值**（见 §3）。

## 2. A9 的意外产出：所谓「双通道」其实是「多份拷贝」

顺着「裸名层到底从哪来」往下挖（`--bg-bg-card` 在 `solo-lite.js` 里命中 **0** → 出处另有其人），
定位到设计系统本体的 CSS：

```
node_modules/@byted-icube/ai-modules-chat/dist/index.css   2857KB   去重自定义属性 1520
node_modules/@byted-icube/solo-lite/dist/index.mjs           1590KB   bg 族定义 109 / 属性 428
node_modules/@byted-icube/solo-lite/dist/floating-chat-entry.mjs 1574KB   同上
node_modules/trae-browser-inspect/dist/file-preview.mjs      6491KB   同上
```

主题钩子也拿到了原文（两种写法**并联在同一条规则里**）：

```
[data-theme=dark]  body.icube-chat-next, body.icube-chat-next.dark      → --bg-bg-base-secondary:#222427; --bg-bg-card:#1f2021; --bg-bg-base-default:#1a1b1d
[data-theme=light] body.icube-chat-next, body.icube-chat-next.light     → #edeff2 / #fafafa / #fff
[data-theme=dark-blue] … , body.icube-chat-next.dark-blue, …            → #232a35 / #1f2021 / #181d27
出现次数：dark 85 · light 75 · dark-blue 75 ·（另有 [data-theme="dark"] 带引号 1 次）
```

然后给脚本加 `--copies` 模式，结果比机制本身更值得记：
**同一个裸名令牌 `--bg-bg-base-secondary` 在装机包里有 9 个文件、两套互不相同的取值。**

| 拷贝 | light | dark | dark-blue | 钩子写法 |
|---|---|---|---|---|
| Set A（`icube-chat-next` 世代） | `#edeff2` | `#222427` | `#232a35` | `[data-theme=…] body.icube-chat-next` |
| Set B（`solo-lite` 世代） | `#f5f5f5` | `#262626` | **`#262626`（与 dark 同值 = 深蓝没实现）** | `[data-theme='…'], .vs.solo-lite` / `.vs-dark.solo-lite` |

一次性解释了三件原本要各记一条的事：

1. **§9.3 里「E40 画布实测 `#f5f5f5`」不是测错**——SOLO 窗口加载的是 Set B；而工作台镜像的 `#222427` 与 Set A 暗色档**逐字节相同**。同名令牌，两个窗口落在不同拷贝上。
2. **多命名空间的漂移是可观测的，不是理论风险**——Set B 的 `dark-blue` 直接复制了 `dark` 的值。这条把 M10 从「暂不做」**判成明确不借鉴**。
3. **静态层不能用来取值**——该文件 `var()` 共 **13740** 次，其中 **4608 次（33.5%）带逗号兜底字面量**；`#f5f5f5` 出现 22 次、20 次是 `var(--bg-bg-base-secondary,#f5f5f5)` 的兜底。**照抄静态 CSS 会抄到兜底值。**

还顺手捡到一个 Trae 的真错：暗色块里 `--shadow-chat-input` 只把 alpha 从 `.08` 提到 `.12`，
**基色仍是 `rgba(24,24,24,…)`**。`#181818` 落在 `#1a1b1d` 上≈不可见。
我们 `index.css` L235–236 是整体换基色到 `rgba(0,0,0,.5)` + 白色发丝 inset——**这条是我们比样本做得对的地方**，
已写进 §11.2，防止将来有人「对齐 Trae」把它改回去。

（A4 深蓝也顺带解了一半：取值已知，但**哪套拷贝最终生效**静态判不了 → 新增 A12，并进 A3/A4 那次开机。）

## 3. A11：把「值得借鉴」逐条撞上自家令牌表

`tools/a11-token-audit.mjs`，**只读**。先立纪律：脚本末尾显式打印「未对 src 做任何写入」，
参数只有读路径，没有任何 write 分支。

清点基线：**定义语句 167 / 去重令牌 104 / 亮暗镜像导致 61 个令牌名出现两次（正常）**。
`src/components`（27 个文件）**硬写 hex = 0、硬写 `rgba()` = 0** →
令牌纪律本来就成立，所以**任何「借鉴」都不许把「补纪律」算成收益**（这条直接砍掉了上一版 §11.3 的第一件事）。

12 条候选的判定（详见 report §11.1 最后一列）：

| 判定 | 条目 | 依据 |
|---|---|---|
| 已有 | M3 主体 / M4 / M6 / M9 / M12 / M1 的方法 | `--sh-1/2/3`（含 `--sh-2` 的 `0 0 0 1px` 分量）、`--border/--border-strong/--control-line`、`--rail-max 900/--tool-rail 1120`、`--sel .09/.14`+暗 `.06/.10`、卡片化裁决 |
| 真缺 | **M7 滚动渐隐遮罩** | 全 `src`：`mask-image` **0** 命中；`mask` 仅 **1** 处（L1377–1380，复选勾的 SVG 遮罩），**不是**渐隐 |
| 小补 | M1 缺档 · M3 缺别名 | `--accent` 5 档（无 `active`）、`--ok/--warn` 各 **2** 档（无 `line`）、`--danger` 3 档；场景别名层 `--shadow-menu/modal` 无 |
| 数值冲突→不借鉴 | M2 / M5 / M8 | 见下 |
| 证据反向→删除 | M10 | A9 §9.2.1 |
| 缺但属需求未定 | M11 | **更正上一版的「已有」**：`src` 里主题入口只有 **1 个** `@media (prefers-color-scheme: dark)`（L204），**没有任何 class/属性钩子**；`styleguide.jsx` L430 明写「暗色跟随系统偏好」，`RtiCompare.jsx` L42 只是监听它取图表色 |

**M5 是最能说明「对账为什么必要」的一条。** 上一版按 Trae 的 32/36px 行节奏 + `#cccccc` 发丝线，
把它列成「可直接抄的排版节拍」。对账发现我们**早就在这么做**：
`.task-row` = `height: var(--row-h)`（L150 `--row-h: 42px`）+ `border-bottom: 1px solid var(--border)`（L1261/L1265）。
差的只是密度取向（我们一行要放三栏，Trae 不放）→ **数值之争不是解析报告的产出**，改判不借鉴。

**M4 / M6 的判定还反过来给了我们两条「我们更严/更细」的结论**：
`--control-line` 带 WCAG 1.4.11 ≥3:1 的语义约束、与装饰发丝线显式分离（Trae 的三级只是同基色改 alpha，**没这个区分**）；
限宽我们按「阅读 / 数据密集」给了两档，Trae 只有一个固定 800。

同值冗余顺手查出两处：`--r-xs` 与 `--r-sm` 同为 `2px`；`--fs-sm` 与 `--fs-md` 同为 `13px`。
（Trae 那边 `Spacer-/spacer-`、`Radius-/radius-` 两代命名并存正是这类冗余长出来的——
**别名比数值更容易骗人**，已进 §12.2 卫生规则。）

## 5. 本轮踩的两个自己的坑（都进 §12.1）

1. **把静态 CSS 的十六进制当生效值**：兜底字面量（33.5%）+ 多拷贝（9 文件/2 套值）两个原因叠加。
   正解：机制可静态定，取值必须运行时定——这两句不矛盾。
2. **`node -e` 内联写复杂检索逻辑**，本轮失败 3 次：全角括号、`'…'+'];`、以及
   **bash 把单引号里的 `<` 也当重定向**（`['<span …']` 直接 syntax error）。
   正解：超过一行的取证逻辑一律落成 `tools/*.mjs` 再跑——顺带天然可复现（已进 §14.2）。
