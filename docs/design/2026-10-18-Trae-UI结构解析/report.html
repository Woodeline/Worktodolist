2. 结论速览（15 条）

#结论分级 / 证据
1Trae 的 UI 不是单页应用，而是 4 个独立渲染目标：workbench、solo-lite（Agent 窗口）、setup（引导）、floatingButton（悬浮球）。任何「在主窗口 DOM 里找 AI 面板」的尝试都是错的。实测·DOM/json/list target 表 notes/00 §2
2「Agent 是独立窗口」指独立 BrowserWindow + 独立渲染进程，不是独立设计体系：三份 CSS 的规则块只差裁剪量（9978 / 9379 / 7143），布局类几乎同量。静态extracted/*.json + notes/02 §3
3工作台纵向骨架实测：标题栏 40 / 主体 800 / 状态栏 20，横向 活动栏 44 / 侧栏 294 / 编辑器 516 / 右侧辅助栏 574，sash 固定 4px。实测·DOM实测·像素E30 · E34 · §5.1
4像素测距与运行时令牌双向对账成功：实测活动栏底色 #222427 = --vscode-activityBar-background，实测内容区 #1a1b1d = --vscode-editor-background。说明测距结果可信，也说明 Trae 未在此层做渐变/纹理。实测·像素+实测·DOME30/E34 · §9.3
5令牌表不可能从 CSS 反查得到：静态 CSS 只有 61（工作台）/47（SOLO）个自定义属性名，运行时 :root 上有 3919 / 4388 个。--vscode-* 由主题服务运行时生成。实测·DOM+静态notes/02 §1
6Trae 自研令牌通过两条通道下发：SOLO/React 层吃裸名 --bg-bg-*，工作台层吃镜像 --vscode-icube--bg-bg-*。机制已在明文 bundle 里坐实（A9）：主题贡献注册 102 个 icube--* 颜色 id + 5 条字面量定义（渐变/滚动阴影，颜色注册表不收非颜色）= 107，与运行时快照的 107 条镜像双向差集为 0（覆盖率 100%）；全量检索没有任何字符串拼接点 → 前缀是打包期命名，不是运行时生成。同名 94 条中 90 条取值不同，原因是两个窗口当时分别处于暗/亮主题。实测·DOME30 × E40 对账 + 静态tools/a9-mirror-hunt.mjs · §9.2
7按裸名统计，自研令牌 SOLO 601 条 vs 工作台 101 条（6 倍）；但把注入 --vscode- 命名空间的 icube 部分算进来后是 1597 vs 1099。结论修正：AI 层不是「另建一套」，而是在同一套之上用了更多细粒度令牌。实测·DOM§9.1（含对 notes/02 的更正）
8Trae 没有自建图标字体，沿用 codicon（1094 个类名，704 条 --vscode-icon-icube-* 只是往 codicon 私有区加字形）。静态+实测·DOMnotes/02 §4
9字体只有两套：SF Pro Text（UI）与 JetBrains Mono（代码）；代码字重 450（非整百，是为该字体做的微调）。实测·DOM--font-family-* · --font-weight-code
10同一产品里存在两套界面语言：工作台是直角分栏（sash 4px、无投影），SOLO 是圆角卡片（radius 16px + 投影、四周 8px 画布留白）。这是给本项目参考时最需要主动取舍的一点。实测·DOM实测·像素E30 vs E40 · §6.2
11引导页全程无需登录即可进入工作台，登录只影响 AI 功能。这是本次能在独立 profile 里拿到真实外壳 UI 的前提，也意味着不需要碰用户凭据。实测·DOMnotes/00 §3
12主题不跨渲染目标同步：引导页选暗色 → 工作台 vs-dark，SOLO 窗口仍是 vs（亮）。所以主题矩阵必须按 target 分别设置与验证，不能假设一个开关管全局。实测·DOMbody.class 比对 · notes/00 §3
13主题信息写在 body.className（vs-dark / vs / theme-icube / solo-lite），不在 data-vscode-theme-name。读错位置会得到「产品未暴露主题」的假结论。实测·DOMnotes/02 §6
14取证方法本身有可复用产出：「连续多格 PNG 字节数/DOM 节点数完全相同 ⇒ 该格无效」。本轮靠这条查出模态「工作区信任」对话框吞掉了 6 格输入。实测·DOMnotes/01 §3
15同一族裸名令牌在 Trae 装机包里至少有 9 个文件、两套互不相同的取值：如 --bg-bg-base-secondary 的亮色档，一份拷贝是 #edeff2（钩子 body.icube-chat-next.light），另一份是 #f5f5f5（钩子 .vs.solo-lite）；暗色档分别是 #222427 与 #262626；而 dark-blue 主题在 solo-lite 那份里根本没实现，直接回落成与 dark 同值。这解释了 §9.3 里「E40 实测 #f5f5f5 对不上 ai-modules-chat 的 #edeff2」——不是测错，是产品内部有多份拷贝。静态tools/a9-mirror-hunt.mjs … --copies --bg-bg-base-secondary · §9.2.1

11.3 A11 之后重排的「若只做三件事」

  2. 补滚动渐隐遮罩（M7，唯一真缺失）：可滚动区底部 mask-image: linear-gradient()，颜色走 --surface 不写死。为什么第二：12 项里只有它是「Trae 有 / 我们 0 命中 / 与现有裁决不冲突」的；单独可验证（截图对比截断处），失败可整体回退。
