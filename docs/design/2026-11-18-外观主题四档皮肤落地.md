## 二改：侧栏四档同形（2026-11-18 15:20）

需求：素纸 / 夜航 / 园庭 三档的侧栏，样式、布局、间距与交互行为全部回落到原版。

首版把侧栏当成了皮肤的「签名」：夜航收成 56px 图标轨（`.nav-label` / `.count` / `.sidebar-group-name` 退场、`.nav-item` 改 36×36 居中、`.sidebar` 内边距 10/6），素纸把 `--nav-h` 抬到 30，园庭把 `.nav-item` 圆角拉到 `--r-lg` 并给选中态染 `--accent-soft`。后果是同一份目录在四档下要点出四套手感 —— 侧栏是唯一的视图导航，藏掉标签等于换了一种用法，而不只是换了一张纸。

### 改了什么

- 令牌层：三档皮肤块删掉 `--nav-h`（30 / 36 / 32）与夜航的 `--sidebar-w: 56px`，侧栏尺寸只剩基线一处。
- 新令牌 `--r-nav: 6px`（§1，基线与 `--r-sm` 同值）：`.nav-item` / `.sidebar-group-toggle` 改读它。皮肤仍在改 `--r-sm`（夜航 8 / 园庭 10），但带不动侧栏 —— 侧栏行的圆角四档同刻，别处继续跟皮肤走。皮肤块不得覆盖 `--r-nav`。
- §9.5：删掉夜航的 `.sidebar` / `.nav-label` / `.count` / `.sidebar-group-name` / `.sidebar-group` / `.sidebar-members` / `.nav-item` / `.sidebar-group-toggle` 八条覆盖，与园庭的 `.nav-item` / `.nav-item.active` 两条。差值只剩「夜航＝读数行行内常驻 + 圆角悬停块」「素纸＝描边快录」「园庭＝列表圆卡 + 日历圆角格 / 胶囊」。
- 交互随结构一起回归：悬停 `--sel`、选中 `--sel-strong` + `--text`、选中计数 `--accent-hover`，四档同一套；`--r-nav` 保证命中区形状不变。

## 二改（2026-11-18 晚）：按设计稿逐构件移植，侧栏四档同形

用户反馈首落地「只是改了一点颜色」，与五案设计稿出入大；要求除侧栏字样 / 行距外尽量对齐设计稿。

- **侧栏四档同形钉成契约**：宽度 / 行高 / 留白 / 行圆角（`--r-nav`）/ 标签计数可见性 / 悬停与选中态一律基线；夜航 56px 图标轨、素纸行距 30、园庭选中淡底三条全撤。`SettingsPage.test.jsx` 三条契约 + `qa-settings.mjs` 链路断言（夜航 `--row-h` 36 / 侧栏仍 176·26）拦回归。
- **逐构件移植**（§9.5 重写）：上下文条高度与底线、快录三形态、夜航行分隔退场 + 圆角悬停块 + 读数行常驻行内、园庭列表圆卡 + 行圆角、浮窗夜航 440 / 园庭 420 无边框 + 读数胶囊形状、园庭日历分离圆角格 + 胶囊 chip、设置页三档卡片化（头带 + 行卡 + 说明退场）、园庭分段全药丸。
- **本轮修掉的观测缺陷**：设置页空组（无 +项目 时）留空头带 → `:has(.settings-fields:empty)` 整卡退场；模式分段 / 皮肤样张 / 密度网格贴卡边 → 非行控件补卡内留白；头带 `letter-spacing: .08em` 撞字距门禁 → 撤（产品禁非零字距）。
- 验证复跑：853 用例 / 52 文件、guard、test:ui（字距 19/19 复绿）、settings 52/52、responsive 665、tools 73、attack 46、CDP 50/50；24 张实拍重拍。

## 五改：上下文条并进标题行后必须行居中（2026-11-18 17:20）

用户贴标题行截图：`全部` 字样与面板开关 / 搜索 / 排序三枚图标「没在行里居中」。像素量他自己的截图（1143×82 @2x）：窗口内容从 y=40 开始，标题行到 y=102，行中线 71；红绿灯中心 70.7（准），而「全部」与图标墨迹中心 79.5–80 —— **比行中线低约 8.5 设备像素（4.25 逻辑像素）**。

原因：皮肤版式差异里写着 `.topbar { height: 40px }`（素纸 / 夜航）、`46px`（园庭），这是「上下文条自成一行」时的尺寸；但 macOS / Windows 有自绘标题栏，TopBar 被搬进 `.titlebar`，行高由 `--titlebar-h` → `--chrome-row-h`（31）定死。`[data-skin="paper"] .topbar`（0,2,0，源码在后）压过 `.titlebar .topbar { height: 100% }`（0,2,0，源码在前），条长到 40 就从 31 的行里往下溢出，条内元素按 40 的中线（20）对齐 —— 正好低 4.5px（园庭 46 → 7.5px）。

改法：皮肤的高度 / 底线 / 纸面规则一律加 `.workspace >` 前缀，只在条自成一行时生效；标题行里的条恒 `height: 100%`，内容照旧靠 `.topbar` / `.crumb` 的 `align-items: center` 落中线。

实测（headless Chrome + CDP，把真实 TopBar 搬进 `.app.has-titlebar > .titlebar` 外壳，四档 × 1143 宽）：

| 档 | 改前 条高 / 内容相对行中线 | 改后 |
|---|---|---|
| 原版 | 30 / −0.5 | 30 / −0.5 |
| 素纸 | 40 / **+4.5**（溢出 9） | 30 / −0.5 |
| 夜航 | 40 / **+4.5**（溢出 9） | 30 / −0.5 |
| 园庭 | 46 / **+7.5**（溢出 15） | 30 / −0.5 |

（−0.5 是标题行 1px 下边框带来的半像素：条占满内容盒 30，光学上就是居中；红绿灯中心 15.35 与之差 0.35px。）

回归防线：`SettingsPage.test.jsx` 的「外观主题：上下文条在标题行里居中（2026-11-18 五改）」两条 —— 皮肤里凡是给 `.topbar` 设 `height` 的选择器必须含 `.workspace > .topbar`；`--titlebar-h` 仍 `var(--chrome-row-h)`、`.titlebar .topbar` 仍 `height: 100%`、`.topbar` / `.crumb` 仍 `align-items: center`。

门禁：`npm test` 52 / **856**、`test:guard` 52 / 856、`test:ui` 全绿（对比度 154 组 0 失败）、`test:settings` 52/52、`npm run build` 通过。
