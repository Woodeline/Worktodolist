## 三改：撤掉卡头的 id / 行号小签（2026-11-18 16:50）

用户贴图指出卡头左上那组 `id:mu1nhm` + `L1` 多余。撤掉两枚小签与整个 `.drawer-meta` 行，改为 `.drawer-topbar` 只装右端关闭钮；`.drawer-meta-id` / `.drawer-meta-ln` / `.drawer-meta-sp` 三条样式与 `lineNo` 计算一并删除（`store.todoEntries` 在组件里仍供嵌套与侧栏计数用）。

实测（760 视口、明暗各一次）：`hasMeta: false`、卡头文本里已无 `id:`，关闭钮 24×24 仍贴右缘；标题纵坐标 322（卡头 278 + 上内边距 14 + 顶栏 24 + 间距 6）**与改前完全一致** —— 撤掉小签没有把标题往上提，窗口高度不变。截图覆盖 `design/assets/2026-11-18-登记卡落地/drawer-{light,dark}.png`。门禁：`npm test` 52 / 854、`test:guard` 52 / 854、`test:ui` 全绿、`test:settings` 52/52、`npm run build` 通过。

## 四改：关闭钮并进标题行，补掉卡顶那片空白（2026-11-18 17:10）

三改后卡头变成「一行只有一枚叉号 + 标题」，用户贴图指出**标题上面一片空白**。原因很直白：卡头上内边距 14 + 关闭钮行 24 + 间距 6 = 44px 里只有一枚叉号，左侧全空，读起来像少渲染了一行。

改法：把关闭钮从独占行挪进标题行（`.drawer-topbar` → `.drawer-headline`），`align-items: center` + `--sp-2` 间距，标题 `flex: 1 1 auto` + `min-width: 0`，卡头上留白收到 **18px**（这一页纸自己的天头）。

选它而不选绝对定位的原因有两条，都写在 CSS 注释里：
- 长标题不会跑到叉号底下 —— 标题是 flex 项，宽度天然让出按钮（实测 27 字标题：标题框 334px、叉号右缘距窗边 17、零重叠，文字在框内自己滚）。
- 标题获得焦点时的 accent 底线**只画到叉号左侧就收住**（实测底线右端 531 / 叉号左缘 539，留 8px）。绝对定位方案得给 input 补 `padding-right`，而底线画在 border box 上，会从叉号底下穿过去。

实测（760 视口，明暗各一次）：卡顶到标题 **44 → 19**、窗口高 **546 → 520**、叉号中心与标题中线偏差 **0**、叉号右缘距窗边 17（`--row-pad` 16 + 1 边框）、点击命中自己；四档皮肤 × 宽边/390 共 8 组，标题字号 18/16 两档下偏差仍为 0、无溢出。截图 `design/assets/2026-11-18-登记卡落地/drawer-head-{light,dark}.png` 与 `drawer-head-long-{light,dark}.png`（长标题）。

门禁：`npm test` 52 / **854**、`test:guard` 52 / 854、`test:ui` 全绿（对比度 154 组 0 失败）、`test:settings` 52/52、`npm run build` 通过。
