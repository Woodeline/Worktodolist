# 子任务只读与优先级底纹（2026-11-25）

两条改动落在同一轮：子任务从「可单独编辑」收回成只读条目；「今日 / 即将到期」两个视图给高优先级整行铺一层淡红提醒，父行一档、子行再淡一档。

## 一、子任务不提供单独编辑

「子任务」的判定统一走 `lib/subtasks.js#isChildInList`：父任务仍在 `todoEntries` 里才算子任务。父被删后子行按顶层渲染（`depth` 归 0），此时它要拿回主行的全部入口，否则会留下一条右键只有两项、快捷键也打不开的死行。

撤掉的入口有四处。

1. 双击与慢双击（`TaskRow` 的 `editable = !isChild`）。
2. 右键菜单：`TaskRow` 的 `handleContextMenu` 在 `readonly` 之后新增 `isChild` 分支，菜单项由导出纯函数 `childMenuItems(task, store)` 生成，只有「标记完成 / 取消完成」与「删除」两项。
3. 全局 `E`（`useHotkeys` 的 `onEdit`）：`store.focusedId && !focusedIsChild` 才打开浮窗。
4. 全局 `Enter`（`onEnter`）：同一道守卫。

改文本的去处仍是父任务的编辑浮窗，子任务区里那条就地编辑行照旧可用。

## 二、高优先级行的淡红提醒

只在 `data-view="today"` 与 `data-view="upcoming"` 的列表里生效。`App` 的两处 `task-list` 容器分别写 `data-view="today"` 与 `data-view={store.view}`，视图一换底色就跟着换。

四枚令牌进 §1，明暗各一套。

| 令牌 | 明 | 暗 |
|---|---|---|
| `--prio-row-bg` | `#fbefed` | `#35211e` |
| `--prio-row-bg-child` | `#fcf1ee` | `#2f1e1b` |
| `--prio-row-bg-hover` | `#f7e5e1` | `#402722` |
| `--prio-row-bg-child-hover` | `#fae7e3` | `#382520` |

选择器写在 `.task-row.row-readonly` 之后，四条规则各带 `:not(.selected)`，选中态保留 `--sel`。父子关系有两条来源同时成立。

- 父行：`task.priority` 为 `A` 时 `TaskRow` 根上带 `prio-high`（`priorityClass` 现由行根持有，列表旗标组件同时存在，两者互不影响）。
- 子行：`rowProps` 按 `t.parentId` 反查父任务，父任务优先级是 `A` 时给子任务下发 `parentHigh`，子行根上带 `parent-prio-high`。子任务自己带 `(B)/(C)` 也照子行档走，提醒跟着整组走。

「中」「低」两档不铺底色。底色是提醒，旗标才是档位刻度，两件事不合并。

## 四、风险

- 深色下子行档与普通行的明度差只有 13 左右（`#2f1e1b` 对 `#1e1d18`），弱于明色。再提一档会贴近父行，选择留在「能看出是一组、又不抢旗标」之间。
- 底纹只说了「高优先级」，没区分「逾期」。逾期仍靠左缘的 `--danger` 竖条与日期色，两者同时出现时红色区域会叠，实测可读，但这是本轮唯一一处色域重叠。

## 五、日志里的撤回（同日追加）

日志（done.txt）的行照旧不改文字，勾选框从只读变成可点：`TaskRow` 多一个 `restorable` prop，只有 `App` 的 done 分支传它。

- 点击走 `toggleComplete` 的取消完成分支（数据层本来就有，之前只是入口被 readonly 挡住）：done.txt 移掉这一行，todo.txt 恢复成未完成行。`reviveTask` 会清 `completed` / `completedAt` 并重写 `raw`，原样保留 `id:` / `parent:` / `rec:` 等标签。
- `readonly` 且 `restorable` 时复选框不再挂 `disabled` 类，提示写「撤回为未完成」；其余只读行（如未识别行）仍是「已完成（只读）」。
- 右键同样给两项，`doneMenuItems` 导出成纯数据：撤回为未完成、复制任务文本。文字编辑入口仍然不开。
- 分组头文案从「日志 · done.txt（只读）」改成「日志 · done.txt」，可撤回之后「只读」这个词已经不准。

验证：`useTodoStore` 新增 R1（done.txt 有行 → 撤回 → done 清空、todo 出现未完成行、盘上 `x 2026-09-25` 前缀消失）；`TaskRow` 三条结构断言（可点 / 不可点 / 菜单两项）。CDP 在 `styleguide.html?view=done` 实点：行数 3 → 2，侧栏「日志」2、「今日」12 → 13、「全部」15 → 16，说明这条真的回到了待办。

风险：撤回归属单向动作，`toggleComplete` 的取消完成分支不入撤销栈，按 Ctrl+Z 不会把这一条重新塞回日志。要再完成一次就再勾一下，代价很低，不值得为它多造一层撤销记录。
