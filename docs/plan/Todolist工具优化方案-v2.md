> 本文档是《Todolist工具完整产品方案.md》v1.0 的审核修订版。
> **口径变更**：v1.0 按"创业产品团队服务海量用户"撰写；v2.0 改为**单人自用工具**口径（Windows 10 单机、无团队、无商业化）。

## 0. 审核结论与核心决策速览

### 0.1 v1.0 审核结论

| 维度 | 评级 | 摘要 |
|---|---|---|
| 文档自洽性 | 中 | 存在 7 处分期交叉矛盾、1 处技术路线自相矛盾（SQLite FTS5 vs Web 主路径）、多处字段级不一致 |

| # | 决策 | v1.0 | v2.0 | 理由 |
|---|---|---|---|---|
| D1 | 执行口径 | 产品化，P0~P4 五阶段 | 个人工具，单阶段交付 M0~M3 | 单人自用无"市场验证"诉求，分期验证逻辑不成立 |

| D6 | 任务状态 | 六态（含进行中/已归档） | 三态：待办 / 已完成 / 已删除（软删 = todo.txt 行移除 + done.txt 追加 + git 兜底） | 归档态在 v1.0 无字段/无视图/无排期，属设计残留 |

## 1. 【增】现状资产评估与 Gap 分析

> v1.0 完全缺失此章。不评估既有资产，新工具第一天就面临"历史数据在哪"与"为何不用现有工具"两个无法回答的问题。

### 1.1 既有资产盘点

| 资产 | 状态 | 说明 |
|---|---|---|
| topydo 0.16（venv + 桌面快捷方式） | ✅ 2026-09-28 实测可用 | todo.txt 格式 CLI：ls / add / do / edit / prompt 交互模式 / columns TUI |
| todo.txt / done.txt | 空文件 | 数据底座就位，无迁移负担 |
| 用户环境 | Win10 + Git Bash + Python 熟练 | 对纯文本文件 + git 工作流零学习成本 |

### 1.2 topydo 已满足 vs 痛点（Gap 分析）

| 能力 | topydo 现状 | 新工具增量价值 |
|---|---|---|
| 录入 | CLI `add`，prompt 模式下可用 | ✅ GUI 常驻浏览器标签页，`n` 键即录，鼠标点选日期 |
| 浏览/筛选 | ls + 表达式过滤（学习成本高） | ✅ 今天/全部视图一键切换，逾期红色标记一目了然 |
| 完成/撤销 | `do` 命令，撤销需手改文件 | ✅ 单击勾选 + Toast 撤销 |
| 优先级/截止日期 | 支持（(A) 语法 / due: 语法，需记格式） | ✅ 点选式设置，免记语法 |
| 统计/热力图 | 无 | ✅ M3 增量（可走 Python 脚本） |
| 提醒 | 无 | ✅ 今日到期区 + 任务计划程序兜底 |

**结论**：topydo 的核心短板是**交互成本**（记语法、开终端）而非能力缺失。新工具定位 = **给 todo.txt 加一层低摩擦 GUI 壳**，两者双轨并存互为备份：GUI 坏了随时退回 CLI，反之亦然。不做"替代"，只做"增强"。

| 协作共享、评论、指派 | 无协作方 | 出现家庭/团队共享诉求 |
| 商业化、付费点 | 自用工具 | 不适用 |

| 甘特图、IM、知识库 | 沿用 v1.0 判断 | 不变 |
| 重型项目管理 | 沿用 v1.0 判断 | 不变 |

## 2. 数据底座设计【改：替换 v1.0 §4 数据模型】

### 2.1 存储决策：todo.txt 文件为唯一数据源

| 候选 | 结论 | 理由 |
|---|---|---|
| **todo.txt 文件（采纳）** | ✅ 主存储 | 社区标准格式；与 topydo 互通；任意编辑器可救援；git 版本化 = 免费备份+历史；8GB 老机零压力 |
| IndexedDB(Dexie) | ❌ 降级为可选缓存 | 浏览器清数据即全灭（v1.0 §9 自认此风险却把备份推到 P2）；仅当 File System Access API 不可用时作为会话缓存兜底 |
| SQLite | ❌ 移除 | 单人千条级数据无查询压力；引 SQLite 即引 Tauri 壳与 Rust 工具链，超出必要复杂度 |

**读写机制**：Chromium 系浏览器（Edge/Chrome，Win10 已具备）通过 **File System Access API** 直读直写工作区下的 `todo.txt` / `done.txt`；目录句柄授权一次后持久记忆。降级链：File System Access API → 手动"打开文件/导出下载"。

### 2.2 todo.txt 格式与字段映射（v1.0 缺失，【增】）

todo.txt 规范语法与内部模型的映射（解析器按官方格式实现）：

| todo.txt 语法 | 内部字段 | 示例 |
|---|---|---|
| 行首 `x YYYY-MM-DD` | status=completed, completed_at | `x 2026-09-30 买牛奶` |
| `(A)`~`(Z)` 行首优先级 | **A/B/C 映射高/中/低，D~Z 原字母透传显示（M0 确认）** | `(A) 交季度报告` |
| 创建日期（优先级后第一个日期） | created_at（topydo add 自动生成，GUI 建任务同样自动补） | `(B) 2026-09-30 写周报` |
| `@context` | 分类（category） | `@工作` |
| `+project` | 标签（tags，多值） | `+搬家` |
| `due:YYYY-MM-DD` | due_date | `due:2026-10-05` |
| `t:YYYY-MM-DD` | 阈值日期：到期前在"今天"视图隐藏（**解析展示，M0 确认**，与 topydo ls 行为一致） | `t:2026-10-05` |
| `star:1` | 星标图标（**解析展示，M0 确认**） | `star:1` |
| 其他 `key:value` | 原样透传保留行尾，编辑不丢失 | — |
| 空行 / `#` 起始行 | 忽略（注释） | — |

内部运行时模型（仅内存/渲染用，不落库）：

```
Task {
  id: 行号 + 内容哈希（会话内标识，不持久化）
  raw: 原始行文本（保存时按规范重排：x (优先级) 日期 标题 @ctx +proj key:val）
  title, priority, category, tags[], dueDate, completed, completedAt, createdAt?
}
```

**规则**：todo.txt 规范本身不含 created_at/updated_at —— **不私有扩展格式**（扩展会破坏 topydo 兼容性），时间追溯依赖 **git 提交历史**（用户已有 Git Bash 习惯，备份目录即 git 仓库）。

### 2.3 保存与并发安全【增】

- 保存策略：变更后 500ms 防抖批量写文件；写前保留上一版本内存副本，写失败回滚 UI 并提示。
- 外部修改检测：窗口聚焦时重新读文件并比对 mtime，发现 topydo/编辑器改过文件则自动重载（有未保存本地变更时弹提示二选一）。
- 原子写入：不自行实现 tmp+rename（File System Access API 对选中目录无 rename 原语），依赖 Chromium `createWritable()` 的内部实现——写入先落交换文件、`close()` 时原子提交覆盖，断电/崩溃时原文件保持完整。【2026-10-06 评审修正：原稿声称「先写 todo.txt.tmp 再重命名覆盖」与代码不符，现改为如实描述】

## 4. 技术选型【改：替换 v1.0 §3】

| 项 | 选型 | 理由 |
|---|---|---|
| 形态 | **浏览器直接访问的 Web 单页**（WorkBuddy 本地静态服务预览 / 发布为应用） | 不上 PWA Service Worker（无离线诉求，文件即数据源）、不上 Tauri/Electron（老机 8GB，桌面壳纯负担） |
| 框架 | React 18 + Vite，**plain JS**（不用 TS 严格模式） | AI 辅助开发对冲学习曲线；砍掉 TS/Zustand/Dexie 三层抽象，状态用 useState/useReducer 足够 |
| 样式 | 轻量 CSS（手写或 Tailwind 单文件引入） | 任务列表 UI 元素少，组件库（MUI/shadcn）属过度引入 |
| 日期 | day.js | 轻量，日期计算够用 |
| 文件访问 | File System Access API（Chromium） | Win10 Edge/Chrome 原生支持；降级为手动打开/下载 |
| 依赖总量 | 目标 ≤ 5 个运行时依赖 | 个人工具维护成本与依赖数成正比 |

> 修复 v1.0 矛盾：搜索方案由"SQLite FTS5"（Web 主路径上不存在该组件）改为内存过滤；虚拟滚动、多用户索引、react-window 全部移除（千条级 DOM 直渲可接受）；MUI/shadcn、Zustand、Dexie 从必选清单移除。

## 5. 页面与信息架构【改：收缩 v1.0 §5】

单页应用，三个区域：

```
┌──────────────────────────────────────────┐
│ 顶栏：[+ 快速添加 n] [搜索 /]  [文件状态●] │
├────────┬─────────────────────────────────┤
│ 侧边栏 │  主列表                          │
│ 今天   │  ┌ 逾期区（红）────────────┐    │
│ 全部   │  ├ 今日到期区──────────────┤    │
│ 已完成 │  ├ 其余任务（分组按分类）──┤    │
│ ──────│  └ 行：勾选|标题|(A)|due|@分类│   │
│ 收集箱 │                                 │
│ @分类… │  （点击行 → 底部/侧滑编辑抽屉）   │
│ +标签… │                                 │
├────────┴─────────────────────────────────┤
│ 底栏：文件同步状态 | 上次保存 | 手动重载    │
```

- 任务编辑抽屉：标题、备注、优先级点选、日期选择器、@分类、+标签。

## 6. 实现要点【改：替换 v1.0 §6】

### 6.1 数据可靠性（v1.0 排到 P2，【改】为首交付优先级）

1. 首交付即含 todo.txt 双向读写 = 天然导入导出。
2. 每日自动备份：首次打开时复制 `todo.txt` → `backup/todo-YYYY-MM-DD.txt`，保留最近 30 份；用户对工作区 `git init` 后即得版本化历史（提供一条初始化命令说明，不代替用户执行）。
3. 原子写入（tmp + rename）+ 写失败 UI 回滚。
4. 空文件/格式损坏兜底：解析失败的行原样保留展示为"未知格式行"，**只读不删**，等待人工处理。

### 6.2 性能（v1.0 按万条设计，【改】按千条设计）

- 千条级全量读入内存，过滤/排序纯内存计算，无虚拟滚动、无索引优化。
- 输入防抖 150ms；若未来数据过万再引入分页（预留 `page` 参数即可，不过早实现）。

### 6.3 质量门【改：可测化】

- todo.txt 解析器/序列化器为纯函数，**必须单元测试覆盖**（官方规范用例：完成行、优先级、多 @/+、非法行）。
- 验收标准见 §7，全部为单机可自动/可人工判定表述，修复 v1.0 的不可测条目（"无漏发""零数据丢失""愿意每天打开"）。

## 7. 阶段划分与验收【改：替换 v1.0 §8 五阶段】

### M0 · 真实使用校准（半天，不写代码）【增】——✅ 已完成（2026-09-30）

**执行结果**：
1. topydo 互操作验证通过：`ls`（优先级+due 排序、`t:` 阈值过滤）、`do`（归档 done.txt）、`revert`（双向恢复）全部正常。
2. ⚠️ 发现陷阱：`topydo undo` **不是撤销命令**，会被静默解释为 `ls` 的搜索词（无匹配时空输出退出 0）。真实撤销命令是 `revert`。GUI 文档与用户须知中必须注明。
3. 字段需求确认（依据 9 月 20 日试玩数据 + 本次确认）：优先级 A/B/C 映射高/中/低 + D~Z 字母透传；解析 `star:`（星标）与 `t:`（阈值隐藏）；其余 key:value 透传；创建日期自动生成。
4. 校准数据集（9 条活跃 + 2 条已完成，覆盖逾期/今日/未来/星标/阈值/上下文/项目全形态）保留在 todo.txt / done.txt 作为开发期测试数据。

### M1 · 核心闭环（约 1 周）

**范围**：todo.txt/done.txt 读写、增删改查、完成/撤销、三级优先级、due 日期、逾期标记、今天/全部/已完成三视图、分类与收集箱、快速添加（含内联语法）、核心快捷键、每日备份。

**验收标准**（修复 v1.0 AC 的分期错位与不可测问题）：

| 编号 | 场景 | 预期结果 |
|---|---|---|
| AC-01 | 输入标题回车创建 | 列表即时出现，todo.txt 中出现该行，刷新后仍在 |
| AC-02 | 勾选完成 | todo.txt 行消失，done.txt 追加 `x 日期` 行，Toast 可撤销，撤销后两文件状态复原 |
| AC-03 | 删除任务 | 行移除 + 当日可撤销；从 git/备份可恢复 |
| AC-04 | 编辑任意字段 | todo.txt 对应行按规范重排，外部 topydo ls 可正确解析 |

### M2 · 效率增强（约 3~5 天）

搜索（内存过滤）、组合筛选、批量操作、拖拽排序、`schtasks` 提醒注册脚本、JSON 导出。验收：搜索响应 < 100ms；schtasks 注册后次日 9 点弹通知（人工验证一次）。

统计热力图（建议 Python 脚本，用户 pandas/matplotlib 熟练）、子任务、重复任务。**每项启动前需重新确认真实需求**（防需求蔓延，见 §8 风险）。

## 8. 风险登记（个人工具口径重写，【改】v1.0 §9）

| 风险 | 影响 | 对策 |
|---|---|---|
| **范围蔓延 / 弃坑烂尾**（单人项目第一风险，v1.0 未列） | 工具做一半，任务没处记 | 双轨策略：todo.txt 底座保证任何时刻可退回 topydo；M3 需求须实测痛感后启动 |
| **File System Access API 兼容性**（Firefox/Safari 不支持） | 换浏览器不可用 | 明确只支持 Chromium 系（用户主用 Edge/Chrome）；降级为手动打开/下载模式 |
| 浏览器标签页被误关 | 无常驻入口 | 收藏夹固定 + （可选）发布为应用获得独立入口 |
| 需求误判（做了用不上的功能） | 浪费工时 | M0 真实使用校准；每功能先问"topydo 是否已满足" |
| 无第二人测试 | 边界 bug 流入自用 | 解析器单测 + AC-07/08 互操作用例作为质量底线 |
| 单文件并发写（GUI 与 topydo 同时写） | 丢失一方变更 | M1 只做"聚焦时检测+提示"，不实现文件锁（单人场景足够）；写前强制重读 |

**【删】v1.0 风险表中不适用的条目**：BaaS 锁定、国内推送碎片化、协作权限漏洞、同步冲突丢数据（对应能力已整体移除）。
